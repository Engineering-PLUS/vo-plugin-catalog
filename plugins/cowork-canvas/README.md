# cowork-canvas

An interactive panel for Claude. Claude opens one panel inside the conversation, keeps it up to date
while it works, and collects what the user answers in it.

> **Generated by `scripts/publish.ps1` in the cowork-canvas repository; edit there.** A hand edit in
> this folder is detected: `BUILD.json` holds a sha256 for every file.

This is an early build: text, tiles, steps, questions and action buttons. Sheets, markups, image tools
and geometry come in later phases.

## How it is wired, and why

The plugin carries the server's files, the skill and the command. It does **not** start the server
itself. The server has to be registered with the desktop app, as shown below.

The reason, found in Cowork on 2026-11-18 (app 5.11492.5): a server that a plugin starts connects and
its tools work, but the app never shows its panel. A server the app manages itself gets its panel. With
both registered the model sees two sets of tools and may pick the plugin's, which has no panel. So the
plugin has no `.mcp.json`.

## Registering the server

Add this to the desktop app's MCP servers (developer settings), or the equivalent entry to the
organisation's managed servers, with the path of this plugin's `server\start.cmd` on that machine:

```json
{
  "mcpServers": {
    "canvas": {
      "command": "cmd.exe",
      "args": ["/d", "/c", "<this plugin's folder>\\server\\start.cmd"]
    }
  }
}
```

Name it `canvas`. The tools then reach the model as `mcp__canvas__<tool>`.

## Prerequisites

- **.NET 10 runtime** (x64) under `C:\Program Files\dotnet`. The pyRevit installer brings it, so a
  seat that has run the pyRevit Utility already has it. Check with `dotnet --list-runtimes`: one line
  must start with `Microsoft.NETCore.App 10.`.

Nothing is downloaded or installed when the server starts. `server/start.cmd` finds `dotnet.exe` and
runs `server/bin/CanvasMcp.dll`.

## Field test

Run `/canvas-demo`. It checks the server's native parts, opens a demo panel, and reports what the
host supports (fullscreen, messages, model context) and how long a call from the panel takes.

## Tools

| Tool | Called by | Does |
|---|---|---|
| `open_canvas` | Claude | Opens a panel from a title and blocks; returns a `canvas_id`. The only tool with a UI. |
| `update_canvas` | Claude | Changes an open panel: set, patch or remove a block, change the title, reopen a question. |
| `await_canvas` | Claude | Waits up to 40 s for the user's answers and button clicks. |
| `get_canvas` | Claude | What a panel shows now, the answers so far, and what the host reported about itself. |
| `close_canvas` | Claude | Marks a panel finished. |
| `canvas_self_check` | Claude | Renders a PDF page to an image to prove the native libraries load; reports runtime and timings. |
| `canvas_sync` | the panel | Long poll for changes, up to 25 s. |
| `canvas_event` | the panel | Stores an answer, a button click or the host report. |

Every tool is read-only from the point of view of the user's files and models. Nothing reaches an
outside service.

## Where canvases are kept

Each canvas is one JSON file in `%LOCALAPPDATA%\cowork-canvas\state` (set `COWORK_CANVAS_STATE` to use
another folder). The app runs more than one process of this server at the same time: one answers the
model's calls and another answers the panel's. They meet in that folder. A canvas is removed two weeks
after its last use.

## Skill and command

| Name | Use it for |
|---|---|
| `canvas-rules` (skill) | Start here: when a panel is worth opening, one panel per task, the block types, asking and collecting an answer, what to do when no panel appears |
| `/canvas-demo` (command) | The field test above |

## Files

| Path | What it is |
|---|---|
| `server/start.cmd` | Finds `dotnet.exe` and runs the server (CRLF line endings) |
| `server/bin/` | The built server: `CanvasMcp.dll`, the packages it uses, and the native PDFium and Skia libraries |
| `server/tools.json` | The tool list the build produced |
| `skills/`, `commands/` | The skill and the command |
| `BUILD.json` | Version, source commit, and a sha256 per file |
| `THIRD-PARTY-NOTICES.md` | Licences of the bundled libraries |
